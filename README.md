# RECESS (가칭) — 고등학생 커뮤니티 발표용 데모

**공개 주소: https://jjangga7004-crypto.github.io/recess-demo/** (main에 푸시하면 GitHub Actions가 자동 배포)

여러 커뮤니티의 학생 관련 글을 한곳에서 발견하고(모아보기), 학생 인증·학교 표시 기반의 RECESS에서 이야기하는 서비스의 시연용 웹앱.
서버·API 키 없이 브라우저(localStorage)만으로 작동한다. 학교·프로필·RECESS 게시글·광고·예시 카드는 모두 가상 데이터다.

> **검증하려는 가설**: 학생들이 여러 사이트를 오가며 찾는 정보를 한곳에서 발견하게 하면 방문할 이유가 생기고, 이후 RECESS 자체 커뮤니티 참여로 이어질 수 있다. — 아직 검증되지 않은 가설이다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5180
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 타입 검사 + 배포용 빌드 → `dist/` |
| `npm run build:artifact` | 한 파일짜리 공유 페이지 → `artifact/recess-demo.html` |

서비스 이름은 가칭이다. `src/config.ts`의 `BRAND`와 `index.html`의 `<title>`만 바꾸면 된다.

## 화면 구조

- **모아보기** (초기 기본 홈) — 외부 커뮤니티 글의 링크와 직접 쓴 소개를 훑어본다. 출처(수만휘·오르비·디시·기타)·주제 필터, 제목·소개 검색, 저장·숨기기·출처 제외, 원문 보기, RECESS에서 이야기하기.
  - **카드를 누르면 원문으로 연결**된다(실제 링크는 새 탭, 예시 카드는 앱 안의 예시 상세).
  - **본문 일부**는 예시 카드와, 출처가 본문 일부 표시를 허락한 경우에만 보인다(`SOURCES[id].excerpt`). 오르비(약관 제4조 2항)·디시(제14조 2항)는 허락 없이는 안 되므로 실제 링크는 `소개` 표시와 함께 직접 쓴 소개만 보여준다. 허락을 받으면 그 출처의 `excerpt`를 `'허용'`으로 바꾸고 카드에 `excerpt`를 넣으면 된다.
  - **인기 주제**(실검처럼 순위 1~8) — 데스크톱은 오른쪽, 모바일은 검색창 아래 띠. 모아보기·RECESS 글(최근일수록·반응이 많을수록 가중, 12시간 기준)과 이 기기의 검색 기록으로 계산한다(`lib/trending.ts`, 후보 주제는 `lib/keywords.ts`). 서버가 없어 전체 사용자 실시간 집계가 아니며 화면에도 그렇게 표시한다.
  - 인기 주제를 누르면 **그 주제의 모아보기 카드와 RECESS 학생 글을 한 화면**에 모은다(예: 「10월 모의고사」 = 10모·10월 학평 표기 포함). 검색어를 넣어도 RECESS 글이 함께 나온다.
- **RECESS** — 데모 학생 인증 후 닉네임·학교·인증 표시·선택형 뱃지와 함께 글·댓글·좋아요를 쓰는 자체 커뮤니티. 지역(대치·중계·목동) 필터는 학교 정보가 실제로 있는 이곳에만 있다.
- **저장** — 모아보기 링크(로그인 없이 이 기기에 저장)와 RECESS 글(데모 프로필별)을 탭으로 나눠 본다.
- 내 프로필(뱃지 표시 설정) · 설정(연결 상태, 직접 등록한 링크, 숨김·차단, 데모 초기화)

## 출처 연결 상태 (2026-10-21 확인)

자동 수집은 **모든 출처에서 꺼져 있다.** 허용 근거를 확인한 출처만 켠다는 원칙에 따라, 아래 이유로 하나도 켜지 않았다. 자세한 근거와 문서 링크는 앱의 **설정 → 출처별 연결 상태**에 있다(`src/data/sources.ts`).

| 출처 | 연결 방식 | 판단 | 근거 |
|---|---|---|---|
| 수만휘 (네이버 카페) | 수동 링크 등록 | 허용 근거 확인 못 함 → 비활성 | 네이버 이용약관·네이버 API 약관을 이번 환경에서 열지 못함. NAVER API HUB 개정(2026-09-20 시행) 특약 2.2~2.4상 검색 API 결과는 다른 콘텐츠와 섞기·순서 변경·AI 활용·광고 결합 금지, 저장은 짧은 기간만. 카페글이 그 API 대상인지는 미확인 |
| 오르비 | 수동 링크 등록 | 자동 수집 금지 → 비활성 | 서비스 이용약관 5.5판(2017-04-17) 제9조 7항(스크레이프·로봇·자동화 도구 금지), 제4조 2항(서면 동의 없는 상업적 복사·전시 금지) |
| 디시 | 수동 링크 등록 | 서면 동의 전 금지 → 비활성 | 이용약관(2026-10-07 시행) 제16조 1항(사전 서면 동의 없는 크롤링 금지), 제11조 1항 13호(자동 수집 금지) |
| 기타 | 수동 링크 등록 | — | 운영자가 확인한 공개 링크 + 직접 쓴 소개만 |

**확인이 필요한 조건**
- 네이버 이용약관·네이버 API 이용약관 원문 (이번 환경에서 접근 불가) — 수만휘 판단의 핵심.
- 네이버 검색 API가 카페글을 다루는지, API HUB 약관이 기존 developers.naver.com 약관을 대체하는지.
- 오르비 약관 제9조 7항의 "딥링크"가 개별 글 링크를 직접 등록하는 것까지 포함하는지 — 실제 운영 전 오르비에 확인.
- 디시 자동 수집을 원하면 디시인사이드의 사전 서면 동의.
- robots.txt는 참고만 했고 재사용 허락으로 보지 않았다.

## 기본으로 들어 있는 실제 링크 12개 (2026-10-21 확인)

운영자가 직접 골라 등록한 실제 공개 글이다(`src/data/curatedLinks.ts`). 로그인 없이 열리는지, 학생에게 보여줘도 괜찮은 내용인지 브라우저로 하나씩 열어 확인했다. 카드에는 주소와 직접 쓴 제목·소개, 원문 게시일만 넣었고 원문 본문·이미지·댓글·작성자 정보·댓글 수는 넣지 않았다.

- 오르비 7개, 디시 3개(수능기출분석·윤리와 사상 갤러리), 기타 2개(한국교육과정평가원 공지, 대입정보포털 어디가)
- 주제: 공부 5 · 일상 3 · 입시 4 · 학교생활 0. 학교생활 주제는 욕설이나 특정 학교가 드러나지 않는 글을 찾지 못해 비워 두었다.
- **수만휘는 0개**: cafe.naver.com이 작업 환경에서 열리지 않아 확인하지 못했다. 발표 기기에서 직접 열어 보고 링크 등록으로 추가한다.
- 제외 기준: 욕설, 시험 문항 오류 같은 검증되지 않은 단정, 정치·외모 주제, 분위기가 어두운 글, 청소년에게 보충제를 권하는 글, 개별 학교 갤러리.
- 오르비 링크는 약관 제9조 7항의 "딥링크" 해석이 불분명하다(설정 화면에 표시). 실제 운영 전에 확인한다.
- 처음 여는 기기와 이전 버전 데이터가 있는 기기 모두에 한 번 들어가고, 사용자가 지운 링크는 다시 살리지 않는다. 원문이 삭제되면 카드의 ⋯ 메뉴나 설정에서 지운다(데모 초기화를 하면 다시 들어온다).

## 수동 링크로 운영하는 방법

1. 브라우저에서 원문을 직접 열어 **로그인·카페 가입 없이 열리는 공개 주소**인지 확인한다.
2. 모아보기의 **링크 등록**(모바일은 하단 + → 링크 등록)을 누른다.
3. 주소를 붙여넣으면 도메인으로 출처가 자동 선택된다(페이지 내용은 가져오지 않는다).
4. **소개 제목과 짧은 소개를 직접 쓴다.** 원문 본문·이미지·댓글·작성자 정보는 옮기지 않는다.
5. 주제를 고르고, 원문 게시일은 확인한 경우에만 넣는다(모르면 비워 두면 '원문 게시 시각 모름'으로 표시).
6. 같은 주소는 중복 등록되지 않는다(주소의 `#`·utm 값은 정리해서 비교).
7. 수정·삭제는 카드의 ⋯ 메뉴 또는 **설정 → 직접 등록한 링크**에서 한다. 원문이 삭제되거나 삭제 요청이 오면 여기서 지운다.

시연 환경에서는 등록한 링크가 그 브라우저에만 저장된다. 발표 기기에서 미리 등록해 두거나 발표 중에 직접 등록하면 된다.

## 60초 시연 순서

발표 직전에 **설정 → 데모 초기화**를 누르고, 등록할 실제 공개 링크 하나를 복사해 둔다(기본 12개에 없는 주소여야 중복으로 막히지 않는다).

발표 기기에서 미리 10월 모의고사 후기 링크를 링크 등록으로 몇 개 넣어 두면 `10월 모의고사`가 인기 주제 위쪽으로 올라온다.

1. **(0–10초) 모아보기** — 첫 화면에서 오르비·디시·기타의 실제 링크 카드가 한 피드에 있다. 상단 안내("자동으로 가져오는 출처는 없어요…")와 `직접 등록` 표시, 카드를 누르면 원문으로 간다는 점을 짚는다.
2. **(10–18초) 인기 주제** — `10월 모의고사`를 누르면 여러 출처의 관련 카드와 RECESS 학생 글이 한 화면에 모인다. 실제 링크는 원문 보호를 위해 `소개`만 보인다는 점을 짚는다. `주제 해제`.
3. **(18–28초) 링크 등록** — `링크 등록` → 복사해 둔 주소 붙여넣기(출처 자동 선택) → 소개 제목·소개 직접 입력 → 체크 → `모아보기에 추가`. 맨 위에 `직접 등록` 카드가 생긴다.
4. **(28–33초) 저장·원문** — 그 카드 `저장` → `원문 보기`로 새 탭에서 원문이 열린다.
5. **(33–48초) RECESS에서 이야기하기** — 같은 카드의 `이야기하기` → 예시 프로필 `쉬는시간러` → 예시 학생증으로 인증 체험 → 링크가 붙은 글쓰기 창에서 의견 작성 → `올리기`. RECESS 피드 맨 위에 `참고한 글`과 함께 올라간다.
6. **(48–55초) 반응** — 그 글에 좋아요, 댓글 하나. 모아보기 카드에 `RECESS 이야기 1`이 생기고 `원문 반응`과 따로 보인다.
7. **(55–60초) 설정** — `설정 → 출처별 연결 상태`에서 출처마다 자동 수집이 꺼진 이유와 확인 날짜를 보여준다.

## 데모로 처리한 부분

- 로그인·실제 재학 확인 없음(예시 학생증 그림으로 흐름만), 데모 프로필은 이 브라우저에만 저장.
- 자동 수집 서버 없음 — GitHub Pages는 정적 호스팅이고, 자동 수집을 켤 허용 근거가 있는 출처가 없다. 출처별 설정(연결 방식·허용 근거·확인 날짜·수집 필드·요청 빈도·저장 기간·혼합/재정렬/광고 허용·마지막 성공·오류)은 `src/data/sources.ts`에 있고, 혼합이 허용되지 않은 자동 수집 출처는 원래 순서대로 따로 보여주는 처리(`partitionForDisplay`)와 승인 대기 상태(`status: 'pending'`)가 들어 있다. 출처가 허락되면 서버 쪽 작업으로 붙이고, API 키는 서버에만 둔다.
- 예시 카드 24개는 가상 소개글이고 원문 주소가 없다(버튼은 앱 안의 예시 상세로 연결). 원문 댓글 수와 본문 일부도 예시 값이다. **기본으로 숨겨져 있고** 설정 → "모아보기에 예시 콘텐츠 보이기"로 켤 수 있다.
- 신고는 기록만, 상담 체험은 전송 없음, 뱃지 기록은 예시.
- 광고는 RECESS 자체 피드와 그 옆에만 있고 모아보기·저장 화면에는 붙이지 않는다.
- 저장 범위: `recess-demo:`로 시작하는 localStorage 키 하나. 데모 초기화는 이 키만 지운다.
